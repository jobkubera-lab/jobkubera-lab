# KUBERA — reviewer quick path

This page is the shortest technical route through the portfolio.

## 1. KUBERA AGENT OS — control and assurance

Start with [KUBERA AGENT OS](kubera-lab/agent-os/).

Look for:
- bounded capabilities rather than unrestricted agents;
- evidence and approval gates;
- idempotency/replay handling;
- explicit failure states;
- safe demo and automated tests;
- Python 3.11–3.13 CI and coverage floor.

## 2. KUBERA TAO LAB — ML evaluation discipline

Open [KUBERA TAO LAB](kubera-lab/kubera-tao-lab/).

Look for:
- temporal train/validation/test separation;
- validation-locked selection;
- strict unseen-property testing;
- leakage controls;
- explicit reporting of weak segments;
- private implementation with a public evidence dossier.

## 3. KUBERA Real Estate OS — product architecture

Open [KUBERA Real Estate OS](kubera-lab/real-estate-os/).

Look for:
- product/system decomposition;
- multi-tenant and governance requirements;
- explicit separation between implemented work and planned capability;
- no production claim without authenticated integration and verification.

## 4. Applied evidence

- [Tender Intelligence](kubera-lab/tender-intelligence/) — deterministic UK procurement qualification, provenance and DRAFT_ONLY output.
- [MCP Lab](kubera-lab/mcp-lab/) — bounded reusable capability servers plus deny-by-default gateway policy.
- [Council AI Service Finder](research/council-ai-service-finder/eval/v0.1/) — deterministic resident-language retrieval evaluation.
- [Community Compass](kubera-lab/dzambala-community-compass/) — provenance-oriented local event/service discovery.

## Portfolio principle

The portfolio intentionally distinguishes **implemented**, **tested**, **private**, **prototype**, and **planned** work. Evidence is preferred over inflated claims.
