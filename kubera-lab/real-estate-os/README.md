# KUBERA Real Estate OS — public product dossier

**Priority #3 in the KUBERA portfolio.**

The implementation repository is private. This dossier exposes product architecture and engineering boundaries without publishing client data, credentials or private code.

## Product direction

KUBERA Real Estate OS is a London-first real-estate AI operating-system concept combining property intelligence, CRM/workflow automation, evidence-led research, analytics, governance and multi-tenant SaaS architecture.

Core operating loop:

```text
Acquire -> Answer -> Qualify -> Nurture -> Convert -> Analyse -> Optimise
```

## Planned capability groups

- property intelligence and comparable-property research;
- explainable property scoring and risk flags;
- buyer/tenant/seller/landlord qualification;
- human-controlled follow-up and booking workflows;
- CRM integration and audit trails;
- agency funnel and channel analytics;
- multi-tenant permissions and data isolation;
- white-label and integration architecture;
- lawful-basis/consent controls for outbound workflows.

## Current verified status

The private repository currently labels itself **Repository bootstrap**. It contains the product definition, governance requirements and Python project structure. Production integrations are **not** claimed unless they are separately authenticated and tested.

That distinction is intentional: architecture, diagrams and README text do not count as a finished feature.

## Engineering completion rule

A capability is complete only when its workflow, data model, permissions, audit behaviour, failure handling and end-to-end verification exist.

## Relationship to KUBERA TAO LAB

[KUBERA TAO LAB](../kubera-tao-lab/) is a separate ML research/evaluation track. It provides evidence around model validation discipline; it is not presented as the production Real Estate OS backend.
